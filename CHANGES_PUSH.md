# Что исправлено в push-уведомлениях

## Исправлено

1. `worker/worker.js`
   - исправлен порядок HKDF: `IKM = ecdhSecret`, `salt = authSecret`;
   - добавлена отдельная случайная 16-байтовая соль сообщения;
   - исправлена цепочка derivation CEK/NONCE;
   - исправлен бинарный заголовок `aes128gcm`: `salt(16) + rs(4) + idlen(1) + keyid(65)`;
   - `rs = 4096`, без ненужного заполнения сообщения до 4096 байт;
   - соблюдается лимит 4096 байт тела push;
   - удаляются подписки при HTTP 404/410;
   - в тестовом API возвращаются реальные HTTP-статусы push service.

2. `docs/sw.js`
   - повышена версия cache до `pillpals-v33`, чтобы iPhone получил новый Service Worker;
   - добавлен более устойчивый fallback `showNotification()`;
   - push handler оставлен максимально простым и совместимым с Safari.

3. `docs/app.js`
   - тестовый push больше не говорит просто «отправлено»;
   - UI показывает, что push был принят push-service;
   - расписание и подписка продолжают отправляться на Worker.

4. `worker/wrangler.toml`
   - приватный VAPID-ключ удалён из открытой конфигурации.
   - его нужно задать командой:
     `wrangler secret put VAPID_PRIVATE_KEY`

## Важно после деплоя

1. В папке `worker` выполнить:
   `wrangler secret put VAPID_PRIVATE_KEY`
2. Затем:
   `wrangler deploy`
3. Обновить GitHub Pages с файлами из `docs/`.
4. На iPhone удалить старую копию PWA с главного экрана и добавить её заново, если Safari продолжает держать старую подписку/Service Worker.
5. Открыть PWA → разрешить уведомления → нажать 🧪.

Для текущего публичного VAPID key старая подписка может продолжить работать. После ротации пары VAPID ключей потребуется повторно включить уведомления на устройствах.
